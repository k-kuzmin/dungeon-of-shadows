# DUNGEON OF SHADOWS
### Action Roguelike — Technical Design Document v1.0

**Стек:** C# 12 + Raylib-cs + NativeAOT (.NET 8)  
**Платформы:** Windows x64, Linux x64, macOS arm64  
**Дата:** Март 2026

---

## 1. Обзор проекта

Dungeon of Shadows — action roguelike с пиксель-арт графикой, процедурной генерацией подземелий и реалтайм-боёвкой. Игрок исследует бесконечно усложняющиеся этажи подземелья, сражается с врагами в реальном времени, собирает лут, прокачивает персонажа и сражается с боссами. Смерть постоянна (permadeath).

| Параметр | Значение |
|----------|----------|
| Жанр | Action Roguelike / Dungeon Crawler |
| Сеттинг | Тёмное фэнтези, подземелья |
| Камера | Вид сверху (top-down), следует за игроком |
| Бой | Реалтайм, атака ближним/дальним боем |
| Смерть | Permadeath, новый забег с нуля |
| Разрешение | 1280×720, масштабируемое окно |
| Размер тайла | 16×16 px (рендер ×2—×4) |
| Целевой FPS | 60 |

## 3. Процедурная генерация подземелий

### 3.1 Алгоритм BSP (Binary Space Partition)

Карта каждого этажа генерируется через BSP-дерево. Пространство рекурсивно делится на секторы, в каждом листе размещается комната, затем комнаты соединяются коридорами L-формы.

| Параметр | Значение |
|----------|----------|
| Размер карты | 60×50 тайлов (базовый), +5×5 на каждые 5 этажей |
| Комнат | 8–14 на этаж |
| Мин. размер комнаты | 5×4 тайла |
| Макс. размер комнаты | 12×10 тайлов |
| Коридоры | Ширина 1–2 тайла, L-форма |
| Спец. комнаты | Стартовая (spawn), лестница вниз, комната босса (каждые 5 этажей) |
| Декор | Факелы, трещины, кости, лужи — не влияют на проходимость |

### 3.2 Туман войны (Fog of War)

Система видимости на основе raycasting (алгоритм Bresenham). Три состояния тайла:

- **Неизвестный** — полностью чёрный, не отрисовывается
- **Исследованный** — видим с затемнением 60%, враги не отображаются
- **Видимый** — полная яркость, все сущности видны

| Параметр | Значение |
|----------|----------|
| Базовый радиус видимости | 7 тайлов |
| Количество лучей | 360 (по 1 на градус) |
| Преграды | Стены блокируют луч, но сами видимы |
| Обновление | Каждый кадр (позиция игрока меняется плавно) |

## 4. Боевая система (Realtime)

Бой происходит в реальном времени. Игрок движется плавно по тайловой карте, атакует мечом или заклинаниями. Враги действуют независимо по собственным таймерам.

### 4.1 Управление

| Клавиша | Действие |
|---------|----------|
| WASD / Стрелки | Движение (плавное, 8 направлений) |
| J / ЛКМ | Атака мечом (ближний бой, дуга 90°) |
| K / ПКМ | Заклинание (дальний бой) |
| L / Shift | Рывок (dash), кулдаун 1с |
| E | Подобрать предмет / взаимодействие |
| I | Открыть инвентарь (пауза) |
| Tab | Мини-карта (полноэкранная) |
| 1–4 | Быстрые слоты (зелья, свитки) |

### 4.2 Формулы урона

```
Phy DMG = (ATK × weaponMult) − (target.DEF × 0.7) + random(−1, +2)
Mag DMG = (INT × spellPower) − (target.RES × 0.5)
Crit    = damage × 1.8, шанс = baseCrit (5%) + перки + экипировка
Dash    = i-frames 0.2с неуязвимости, кулдаун 1.0с
```

### 4.3 Атака мечом

Атака — дуга 90° перед игроком в направлении последнего движения. Длительность анимации 0.25с. Кулдаун зависит от оружия (0.3–0.8с). Попадание проверяется через пересечение сектора с hitbox-ами врагов.

## 5. Враги и скейлинг

Враги скейлятся по формуле: `stat = base × (1 + floor × 0.15)`. Новые типы открываются каждые 2 этажа. Количество врагов в комнате: 1–3 (этаж 1–4), 2–5 (этаж 5–10), 3–7 (этаж 11+).

### 5.1 Бестиарий

| Имя | HP | ATK | DEF | XP | Этаж+ | AI поведение |
|-----|---:|----:|----:|---:|------:|-------------|
| Rat | 8 | 2 | 0 | 5 | 1 | Бегает к игроку, убегает при HP<30% |
| Goblin | 15 | 4 | 1 | 10 | 1 | Стрейфит, атакует сбоку |
| Skeleton | 20 | 6 | 2 | 15 | 3 | Медленный, бьёт сильно, патрулирует |
| Orc | 30 | 8 | 3 | 25 | 5 | Чарджит к игроку с ускорением |
| Dark Mage | 18 | 10 | 1 | 30 | 7 | Держит дистанцию, стреляет проджектайлами |
| Minotaur | 50 | 12 | 5 | 50 | 9 | Бьёт AoE, разбег + удар |
| Shadow | 25 | 14 | 0 | 40 | 11 | Телепортируется, атакует со спины |
| Golem | 80 | 10 | 8 | 60 | 13 | Очень медленный, огромный HP/DEF |

### 5.2 Боссы (каждые 5 этажей)

- **Этаж 5 — Skeleton King** (HP: 150, 3 фазы: меч, призыв скелетов, бешенство)
- **Этаж 10 — Dragon Wyrm** (HP: 300, огненное дыхание конусом, взлёт + AoE)
- **Этаж 15 — Lich Lord** (HP: 250, телепорты, проклятия, некромантия)
- **Этаж 20+ — процедурные боссы** со случайными комбинациями способностей

## 6. Магия и заклинания

Заклинания расходуют MP. Мана восстанавливается медленно (основа: 1 MP/3с) или через зелья. Заклинания находятся в виде свитков, одновременно можно носить 3 заклинания.

| Заклинание | Описание |
|-----------|----------|
| Magic Bolt (3 MP) | Проджектайл по направлению, урон = INT×2 |
| Fireball (8 MP) | Взрыв AoE 3×3 тайла, урон + поджог (3 тика) |
| Frost Nova (6 MP) | AoE вокруг игрока, замедление 60% на 3с |
| Chain Lightning (10 MP) | Молния прыгает между 3–5 врагами |
| Shadow Step (5 MP) | Телепорт на 5 тайлов + i-frames 0.3с |
| Heal (7 MP) | Восстановление 20 + INT×1.5 HP |

## 8. Прокачка и перки

Опыт накапливается за убийство врагов. XP для следующего уровня = предыдущий × 1.5. При каждом level up игрок выбирает 1 из 3 случайных перков. Игра ставится на паузу на время выбора.

## 9. Рендеринг и визуал

### 9.1 Пиксель-арт тайлсет

Вся графика — один тайлсет (spritesheet) с тайлами 16×16 px, рендерятся с масштабом ×3 (48×48 px на экране). Raylib загружает .png, настройка `TEXTURE_FILTER_POINT` для чёткого пиксель-арта.

| Категория | Спрайты |
|-----------|---------|
| Окружение | Стены (×4 варианта), пол (×3), коридор, дверь, лестница |
| Декор | Факел (аним. 4 кадра), трещины, кости, лужи, сундук |
| Игрок | Idle (4к), ходьба (6к), атака (4к), дэш (3к), смерть (4к) |
| Враги | Idle (4к) + атака (3к) + смерть (3к) на каждый тип |
| Предметы | Иконки оружия, брони, зелий, свитков, золота |
| Эффекты | Слэш меча, огонь, лёд, молния, хил, кровь |

### 9.2 Камера

Плавное следование за игроком через линейную интерполяцию (lerp, фактор 0.08). Лёгкий screen-shake при получении урона (амплитуда 3px, затухание 0.15с).

### 9.3 Частицы

Лёгкая система частиц для визуального фидбэка: числа урона (всплывают и исчезают), искры при ударах, огонь факелов, след дэша, лут-фонтан при смерти врага. Пул 256 частиц, переиспользование по старшинству.

## 10. Пользовательский интерфейс

- **HUD** (верх экрана): полоски HP/MP/XP, уровень, золото, номер этажа
- **Мини-карта** (правый верхний угол): исследованные комнаты, позиция игрока, лестница. Tab — полноэкранный режим
- **Лог событий** (низ экрана): последние 5 сообщений, цветовое кодирование
- **Быстрые слоты** (низ по центру): 4 ячейки с кулдаунами
- **Экран инвентаря** (I): сетка предметов + слоты экипировки, пауза игры
- **Экран выбора перка**: 3 карточки, пауза игры
- **Экран смерти**: статистика забега (этаж, враги, лут, время)

## 11. Архитектура

Проект использует лёгкий ECS-подход без внешних фреймворков. Entity — это int ID. Components — структуры данных. Systems — статические методы, обрабатывающие компоненты.

### 11.1 Game Loop

```csharp
while (!Raylib.WindowShouldClose())
{
    float dt = Raylib.GetFrameTime();
    
    InputSystem.Update(dt);
    PhysicsSystem.Update(dt);       // movement + collision
    CombatSystem.Update(dt);        // attacks + damage
    AISystem.Update(dt);            // enemy behavior
    ProjectileSystem.Update(dt);    // projectiles
    StatusSystem.Update(dt);        // buffs, debuffs
    ParticleSystem.Update(dt);      // vfx
    FOVSystem.Update();             // visibility
    CameraSystem.Update(dt);        // smooth follow
    
    Raylib.BeginDrawing();
    RenderSystem.Draw();            // tiles, entities, UI
    Raylib.EndDrawing();
}
```
